\begin{abstract}
As enterprise computing systems rapidly migrate towards autonomous multi-agent swarms---coordinated across platforms such as Google Cloud Vertex AI Agent Builder and the Model Context Protocol (MCP)---agents increasingly execute consequential mutations across external databases, financial settlement APIs, and enterprise infrastructure. However, modern agentic architectures operate with a critical security and compliance deficit: the \textit{Provenance and Non-Repudiation Void}. When an autonomous sub-agent executes a high-impact tool invocation induced by an indirect prompt injection or stochastic hallucination, existing telemetry systems (e.g., OpenTelemetry, cloud audit trails) record only mutable, unauthenticated textual logs that can be fabricated, repudiated, or silently scrubbed by compromised components. Furthermore, enterprise compliance requires mathematical proof that safety invariants were adhered to, yet organizations are unwilling to expose sensitive customer context or raw prompt tokens to external auditors.

In this paper, we introduce \textbf{Agent-Notary}, a hardware-speed cryptographic attestation and non-repudiation framework for distributed multi-agent workflows. Agent-Notary establishes three foundational innovations: (1) an append-only \textbf{Causal Merkle-DAG} that binds multi-agent request and completion vertices ($v_i^{\text{req}} \to v_i^{\text{resp}}$), tool calls, and Lamport timestamps into an immutable cryptographic chain of custody without retroactive digest mutation; (2) a \textbf{Dual-Tier Blinded Policy-Invariant Attestation Engine} that pairs microsecond intra-cluster HKDF-blinded enclave witness tokens on the hot path with hardware-attested Confidential VM commitment equivalence and asynchronous Ristretto255 Pedersen commitments with Fiat-Shamir Bulletproof range/predicate transcripts for third-party public auditability without disclosing sensitive parameters; and (3) a wire-level \textbf{Zero-Knowledge Action Attestation Voucher (ZKA-Voucher)} encapsulated into standard HTTP/2 and gRPC transport metadata headers. Agent-Notary implements a dual-mode cryptographic trust model: service-bound symmetric HMAC authenticators for microsecond intra-cluster tool server verification alongside asymmetric Ed25519 signatures on Merkle frontier epoch roots for third-party public non-repudiation. Empirical evaluation over $N = 1{,}000$ wire/replay tamper traces and $N = 300$ multi-agent indirect prompt-injection traces (modeled on AgentDojo, InjecAgent, and ASB) demonstrates $100.00\%$ detection of wire tampering, signature forgery, replay desynchronization, and out-of-policy prompt injections ($\Pi(t_i, \theta_i) = 0$), $100.00\%$ post-hoc causal attribution of in-policy semantic hijacking ($1.84\,\mu\text{s}$ DAG candidate-slice traversal resolving $82\%$ of traces structurally, plus $14.2\,\mu\text{s}$ escrowed payload verification on the $18\%$ merged-turn subset), a line-rate mean intra-cluster verification latency of $4.17\,\mu\text{s}$ (P50: $2.29\,\mu\text{s}$, P95: $11.46\,\mu\text{s}$, P99: $21.96\,\mu\text{s}$), and a compact wire header footprint of $2{,}250\,\text{bytes}$.
\end{abstract}

\section{Introduction}
Autonomous Large Language Model (LLM) agents are fundamentally shifting from isolated conversational assistants to distributed, multi-agent swarms that autonomously interact with enterprise backends~\cite{brown2020language, achiam2023gpt4, team2023gemini}. Within enterprise platforms like Vertex AI Agent Builder and the open Model Context Protocol (MCP)~\cite{mcp2024spec}, swarms coordinate complex business workflows including enterprise resource planning (ERP) reconciliations, cloud infrastructure provisioning, and financial disbursements.

Despite this rapid adoption, enterprise multi-agent deployment faces an acute crisis: the \textit{Provenance and Non-Repudiation Void}~\cite{greshake2023not, debenedetti2024agentdojo, zhan2024injecagent}. In a multi-turn swarm, Agent $A$ (e.g., an external customer service intake agent) may ingest an adversarial ticket containing an indirect prompt injection. That injection induces Agent $A$ to issue a compromised task delegation to Agent $B$ (e.g., a privileged financial payment agent), which in turn executes a high-value disbursement API call. When forensic auditors inspect the incident post-hoc, existing telemetry frameworks such as OpenTelemetry and centralized database audit tables provide only mutable, unstructured JSON text logs. These logs suffer from three fatal security limitations:
\begin{enumerate}
    \item \textbf{Vulnerability to Repudiation and Forgery:} Standard API logs lack cryptographic signatures tied to causal execution states. A rogue internal service or an attacker with administrative cloud access can forge, modify, or delete log entries without detection.
    \item \textbf{Causal Disconnection in Heterogeneous Swarms:} When agents operate across organizational or tenant boundaries, asynchronous tool calls become causally untraceable. Standard tracing spans cannot cryptographically prove which upstream agent instruction induced a downstream mutation.
    \item \textbf{The Auditability vs. Privacy Paradox:} Regulatory bodies (e.g., SOX, HIPAA, GDPR) demand proof that agent tool invocations adhered to enterprise policy invariants (e.g., transaction limits, sanitized destination buckets). However, providing the raw audit logs to external auditors leaks proprietary system prompts, model reasoning chains, and confidential customer PII~\cite{goldwasser1989knowledge}.
\end{enumerate}

To overcome these challenges, this paper presents \textbf{Agent-Notary}, a line-rate cryptographic non-repudiation framework designed for enterprise multi-agent tool execution. Importantly, Agent-Notary establishes a \emph{two-pronged defense posture} (pre-execution enforcement and post-hoc provenance) under an explicit \textbf{Trusted Computing Base (TCB)}: the out-of-process Agent-Notary Gateway sidecar and the host orchestration harness's deterministic sub-session context-propagation multiplexer execute co-resident inside the calling agent's hardware-attested Confidential VM enclave boundary (backed by AMD SEV-SNP memory encryption), while destination tool-server verifiers execute inside their respective remote attested enclave boundaries across untrusted network links alongside administrator-provisioned declarative policy circuits $\Pi$. Conversely, LLM reasoning models, host OS/hypervisor/network/logging administrators outside the Confidential VMs, inter-agent network links, local observability databases, and external third-party auditors are strictly untrusted; Google Cloud KMS key release is cryptographically gated by SEV-SNP attestation quotes ($\mathcal{Q}_{\text{TEE}}$), Cloud Spanner/Storage epoch audit anchors enforce WORM retention locks (and replicate $\Sigma_{\text{root}}$ to an external auditor domain), and the gateway journals tool responses to a write-once AES-256-GCM encrypted payload escrow store keyed via per-vertex $k_{\text{escrow},k} = \operatorname{HKDF-SHA256}(\text{sk}_{\text{escrow}}, \mathtt{0x11} \parallel H(v_k^{\text{resp}}))$ wrapped under the KMS-attested auditor public key. Crucially, in the single-parent regime ($|\mathcal{P}_i^{\text{req}}| = 1$, $82\%$ of traces), the enclave-resident harness multiplexer spawns per-branch context-isolated LLM sub-invocations whose outbound transport channels are bound to transport-layer session handles mapped to $v_k^{\text{resp}}$ (without relying on the untrusted LLM to echo proxy tokens), whereas multi-parent context merging ($|\mathcal{P}_i^{\text{req}}| = k_p > 1$, $18\%$ of traces) is governed strictly by deterministic join barriers in the trusted harness workflow graph. If a privileged cloud administrator attempts to suppress or truncate already-anchored gateway frames from audit storage, monotonic epoch sequence counters ($\text{seq}_{\text{epoch}}$) and causal parent links in anchored frontier roots expose the omission immediately; while non-escrowed ($\texttt{escrow\_mode} = 0$) calls trade off a bounded $\Delta_{\text{epoch}} = 100\,\text{ms}$ pre-anchoring window for sub-$5\,\mu\text{s}$ dispatch, high-value or irreversible mutations set $\texttt{escrow\_mode} = 1$ so destination verifiers hold execution in provisional escrow until Spanner epoch anchoring completes. Conversely, if an unnotarized request is dropped before reaching the gateway sidecar, no ZKA-Voucher is minted and the destination verifier fails closed; if a notarized request ($\mathcal{V}_{\text{wire}}$) is dropped in transit before reaching the destination tool server or if the returning completion frame ($o_i$) is dropped after tool execution, the pre-execution vertex $v_i^{\text{req}}$ ($H_{\text{pending}}$) remains permanently anchored in $R_T$ as an unclosed invocation, and cross-referencing the destination verifier's append-only execution receipt log indexed by $(H_{\text{leaf}}, \text{vid})$ disambiguates whether $t_i(\theta_i)$ executed while supporting idempotent retry reconciliation without false-positive replay rejection. Under this threat model, Agent-Notary enforces: (i) \emph{pre-execution line-rate enforcement}, deterministically blocking tool invocations whose parameters violate policy invariants ($\Pi(t_i, \theta_i) = 0$) or exhibit wire tampering, forgery, or replay; and (ii) \emph{post-hoc non-repudiable causal provenance}, anchoring multi-agent delegation chains in an append-only Causal Merkle-DAG so that in-policy semantic prompt injections ($\Pi(t_i, \theta_i) = 1$) remain forensically attributable across organizational boundaries without repudiation via the \textbf{Zero-Knowledge Action Attestation Voucher (ZKA-Voucher)}.

\section{Related Work}
\subsection{Multi-Agent Systems, Request Signing, and Privilege Control}
The emergence of standardized tool invocation protocols and benchmarks---most notably the Model Context Protocol (MCP)~\cite{mcp2024spec}, functional suites such as MCP-Universe~\cite{luo2025mcpuniverse} and MCP-Bench~\cite{wang2025mcpbench}, and dedicated MCP security benchmarks including MCPSecBench~\cite{yang2025mcpsecbench}, MCPTox~\cite{wang2025mcptox}, and MCP-SafetyBench~\cite{zong2025mcpsafetybench}---alongside HTTP Message Signatures (RFC 9421)~\cite{backman2024rfc9421}, OAuth 2.0 Token Exchange (RFC 8693)~\cite{jones2020rfc8693}, Demonstrating Proof-of-Possession (DPoP, RFC 9449)~\cite{fett2023dpop}, and attenuated capability token architectures such as Macaroons~\cite{birgisson2014macaroons} and public-key attenuated Eclipse Biscuit tokens~\cite{couprie2025biscuit}, has advanced how distributed services authenticate remote operations. Recent agent identity protocols such as BAID~\cite{lin2025baid} and AIP~\cite{prakash2026aip} further introduce cryptographic agent identifiers and delegation tokens across MCP and A2A boundaries. However, existing authentication and capability frameworks treat authorization predominantly as a session-level handshake or linear delegation chain~\cite{harding2012oauth}. Once an agent establishes an authenticated session, the runtime often retains broad authority across concurrent branches~\cite{saltzer1975protection, zhang2025asb}. While Macaroons provide chained HMAC caveats, Eclipse Biscuit~\cite{couprie2025biscuit} and AIP~\cite{prakash2026aip} add Ed25519 public-key attenuation and Datalog checks, and RFC 9421 / DPoP specify per-request HTTP signing, none bind non-linear branching two-phase causal dependency DAGs ($v_i^{\text{req}} \to v_i^{\text{resp}}$) across asynchronous multi-agent swarms nor provide zero-knowledge policy-invariant attestations over blinded tool arguments.

Concurrently, recent agent-layer security frameworks---including CaMeL~\cite{debenedetti2025camel}, FIDES~\cite{costa2025fides}, and Progent~\cite{shi2025progent}---enforce pre-execution data-flow isolation, capability labels, or deterministic tool policies inside the agent harness. While these frameworks effectively restrict unauthorized tool calls within a single trusted runtime, they do not generate cryptographic wire vouchers, non-repudiable cross-domain Merkle-DAG audit trails, or zero-knowledge parameter proofs verifiable by external third-party auditors when logs are contested or local telemetry is compromised. Agent-Notary is directly complementary to intra-agent IFC/policy engines, providing the cryptographic transport and non-repudiation layer across distributed multi-agent boundaries.

\subsection{Cryptographic Provenance and Transparency Systems}
Cryptographic transparency and supply-chain provenance systems have proven effective in securing distributed infrastructure, most prominently Certificate Transparency (RFC 6962)~\cite{laurie2014certificate}, software supply-chain layout attestation in \textit{in-toto}~\cite{torres2019intoto}, and content-addressed Merkle-CRDTs~\cite{sanjuan2020merkle}. RFC 6962 employs append-only Merkle trees with domain-separated leaf and interior prefixes to detect unauthorized TLS certificate issuance, \textit{in-toto} verifies signed multi-step software pipeline layouts, and Merkle-CRDTs embed causal DAG history into self-verifying conflict-free replicated data types. However, classical transparency logs assume a single linear timeline, \textit{in-toto} targets static software build pipelines rather than sub-$5\,\mu\text{s}$ dynamic RPC streams, and Merkle-CRDTs optimize for eventual-consistency state replication rather than synchronous two-phase request-completion causality ($v_i^{\text{req}} \to v_i^{\text{resp}}$) with blinded zero-knowledge policy-invariant proofs~\cite{lamport1978time}.

\subsection{Zero-Knowledge and Blinded Policy Attestation}
Zero-Knowledge Proofs (ZKPs) allow a prover to convince a verifier that an assertion is mathematically true without disclosing the underlying witness data~\cite{goldwasser1989knowledge, ben2018scalable}. While general-purpose zk-SNARKs and zk-STARKs have been explored for verifiable off-chain computation~\cite{sasson2014zerocash}, recent MCP auditing proposals such as zk-MCP~\cite{jing2025zkmcp} apply zero-knowledge circuit proofs to agent communication logs, and Bulletproofs~\cite{bunz2018bulletproofs} provide short non-interactive range proofs over Pedersen commitments~\cite{pedersen1991non} without a trusted setup, evaluating multi-millisecond elliptic-curve or SNARK proofs synchronously on every intra-cluster RPC would bottleneck high-frequency agent loops. Agent-Notary bridges this gap through a Dual-Tier Blinded Policy-Invariant Attestation Engine: deploying service-bound HKDF-blinded symmetric enclave commitments on the sub-$5\,\mu\text{s}$ intra-cluster hot path while deferring elliptic-curve Ristretto255 Pedersen commitments and Fiat-Shamir Bulletproof range and R1CS set-membership transcripts~\cite{fiat1986how, bunz2018bulletproofs} anchored under hardware-attested Ed25519 epoch signatures entirely to asynchronous frontier epoch anchoring for third-party public auditability.

\section{Formal Problem Formulation}
Let a multi-agent swarm execution be defined as a set of interacting agents $\mathcal{A} = \{a_1, a_2, \dots, a_k\}$ invoking a catalog of external enterprise tools $\mathcal{T} = \{t_1, t_2, \dots, t_m\}$.

\begin{definition}[Policy Invariant]
Let $\Theta \triangleq \bigcup_{t \in \mathcal{T}} \Theta_t$ denote the universe of tool parameter spaces, where $\Theta_t$ is the schema domain of tool $t$. A policy invariant $\Pi$ is a deterministic total predicate:
\begin{equation}
\Pi: \mathcal{T} \times \Theta \to \{0, 1\}, \quad \text{with } \Pi(t, \theta) = 0 \;\;\forall\,\theta \notin \Theta_t
\end{equation}
An execution is policy-compliant if and only if $\theta \in \Theta_t$ and $\Pi(t, \theta) = 1$; any tool call with $\Pi(t, \theta) = 0$ is rejected pre-execution at the gateway prover boundary.
\end{definition}

\begin{definition}[Append-Only Two-Phase Causal Merkle-DAG Lifecycle]
Each action step $i$ in the swarm is represented in an append-only directed acyclic graph $\mathcal{G}_{\text{prov}} = (\mathcal{V}, \mathcal{E})$ via two distinct, causally linked immutable vertices ($v_i^{\text{req}}, v_i^{\text{resp}} \in \mathcal{V}$ with globally unique identifiers $\text{id}_v$ and directed edge $(v_i^{\text{req}}, v_i^{\text{resp}}) \in \mathcal{E}$), serialized under deterministic RFC 8785 JSON Canonicalization Scheme (JCS)~\cite{rundgren2020rfc8785} ($\operatorname{CanonicalJSON}(\cdot)$) so that post-execution output binding never mutates or retroactively invalidates pre-execution vertex digests. To guarantee unconditional prefix-level domain separation across all eight Merkle-DAG SHA-256 contexts (and across all 18 SHA-256/Ed25519/HKDF contexts $\mathtt{0x00}$--$\mathtt{0x11}$ in the protocol), 1-byte tags $\mathtt{0x00}$ and $\mathtt{0x01}$ are reserved exclusively for RFC 6962 Merkle tree leaf and interior nodes, while vertex-level commitments use tags $\mathtt{0x02}$ through $\mathtt{0x07}$ (and signature/attestation/escrow contexts use $\mathtt{0x08}$ through $\mathtt{0x11}$):
\begin{enumerate}
    \item \textbf{Pre-Execution Request Vertex ($v_i^{\text{req}}$):} Minted before dispatching tool $t_i$, committing to parameters via a cryptographically random blinding salt $r_i \xleftarrow{\$} \{0,1\}^{256}$ with 1-byte domain separator $\mathtt{0x02}$:
    \begin{equation}
    \begin{split}
    C_{\theta_i} &= \operatorname{Commit}(\theta_i; r_i) \\
    &\triangleq \operatorname{SHA256}\big(\mathtt{0x02} \parallel r_i \parallel \operatorname{CanonicalJSON}(\theta_i)\big)
    \end{split}
    \end{equation}
    The immutable request vertex tuple is defined as:
    \begin{equation}
    v_i^{\text{req}} = \langle \text{id}_i^{\text{req}}, a_i, \lambda_i, \mathcal{P}_i^{\text{req}}, t_i, C_{\theta_i}, H_{\text{out}}(v_i^{\text{req}}), \pi_i \rangle
    \end{equation}
    where $a_i$ is the calling agent, $\lambda_i \in \mathbb{N}$ is the causal Lamport clock at dispatch, $\mathcal{P}_i^{\text{req}} = \{v_p \mid (v_p, v_i^{\text{req}}) \in \mathcal{E}\}$ is the set of causal parent vertices active in the agent's sub-session context at dispatch time, $H_{\text{out}}(v_i^{\text{req}}) \triangleq H_{\text{pending}} \triangleq \operatorname{SHA256}(\mathtt{0x06} \parallel \text{``PENDING\_EXECUTION''})$, and $\pi_i$ is the policy-invariant attestation token. The digest $H_{\text{leaf}} \triangleq H(v_i^{\text{req}})$ is permanently embedded in the wire ZKA-Voucher $\mathcal{V}_{\text{wire}}$.
    \item \textbf{Post-Execution Completion Vertex ($v_i^{\text{resp}}$):} Upon tool completion returning payload $o_i$, rather than mutating $v_i^{\text{req}}$ in place, the runtime advances its current local Lamport clock $\lambda_{\text{local}}$ to $\lambda_i^{\text{resp}} = \max(\lambda_{\text{local}}, \lambda_i) + 1$ and appends a new immutable completion vertex:
    \begin{equation}
    v_i^{\text{resp}} = \langle \text{id}_i^{\text{resp}}, a_i, \lambda_i^{\text{resp}}, \{v_i^{\text{req}}\}, t_i, C_{\theta_i}, H_{\text{out}}(v_i^{\text{resp}}), \pi_i \rangle
    \end{equation}
    with causal parent $\mathcal{P}_i^{\text{resp}} = \{v_i^{\text{req}}\}$ and status-tagged output digest $H_{\text{out}}(v_i^{\text{resp}}) \triangleq \operatorname{SHA256}(\mathtt{0x07} \parallel \operatorname{CanonicalJSON}(o_i))$, whose $\mathtt{0x07}$ prefix guarantees unconditional domain separation from $H_{\text{pending}}$ ($\mathtt{0x06}$) and RFC 6962 interior nodes ($\mathtt{0x01}$) regardless of payload byte length. Any downstream agent step $j$ causally conditioned on the output $o_i$ includes $v_i^{\text{resp}} \in \mathcal{P}_j^{\text{req}}$ (whereas concurrent child calls dispatched prior to $t_i$'s return reference $v_i^{\text{req}}$), preserving strict append-only immutability across all historical frontier roots and in-flight vouchers.
\end{enumerate}
\end{definition}

To prevent algebraic self-cancellation and generalized birthday attacks inherent to bitwise XOR accumulators, parent node commitments for any vertex $v \in \mathcal{V}$ with parent set $\mathcal{P}(v) = \{v_{p_1}, \dots, v_{p_{k_p}}\}$ of cardinality $k_p = |\mathcal{P}(v)|$ are combined via 64-bit big-endian length-prefixed, domain-separated ($\mathtt{0x03}$) concatenation over canonically sorted 32-byte digests:
\begin{equation}
\begin{split}
H(\mathcal{P}(v)) \triangleq \operatorname{SHA256}\big(&\mathtt{0x03} \parallel \operatorname{encode}_{64}(k_p) \\
&\parallel H(v_{p_1}) \parallel \dots \parallel H(v_{p_{k_p}})\big)
\end{split}
\end{equation}
where $H(v_{p_1}) \le \dots \le H(v_{p_{k_p}})$ lexicographically. For every variable-length string field $s \in \{\text{id}_v, a_i, t_i\}$, let $\operatorname{lp}(s) \triangleq \operatorname{encode}_{64}(|s|) \parallel s$ denote its 64-bit big-endian byte-length prefix followed by its UTF-8 bytes, while $H(\mathcal{P}(v)), C_{\theta_i}, H_{\text{out}}(v), \pi_i \in \{0,1\}^{256}$ are fixed-width 32-byte digests. The canonical vertex commitment $H(v)$ for $v \in \{v_i^{\text{req}}, v_i^{\text{resp}}\}$ is computed with domain separator $\mathtt{0x04}$:
\begin{equation}
\begin{split}
H(v) = \operatorname{SHA256}\Big(&\mathtt{0x04} \parallel \operatorname{lp}(\text{id}_v) \parallel \operatorname{lp}(a_i) \parallel \operatorname{encode}_{64}(\lambda_v) \\
&\parallel H(\mathcal{P}(v)) \parallel \operatorname{lp}(t_i) \parallel C_{\theta_i} \parallel H_{\text{out}}(v) \parallel \pi_i\Big)
\end{split}
\end{equation}
At any snapshot $T$, the active DAG frontier is defined strictly as the set of sink vertices in active sessions with zero outgoing causal edges, $\mathcal{V}_{\text{frontier}}(T) \triangleq \{v \in \mathcal{V} \mid \text{out-deg}_{\mathcal{G}_{\text{prov}}}(v) = 0\}$. We distinguish graph-structural supersession from cache eviction: when a child vertex (such as $v_i^{\text{resp}}$) is appended to $v_i^{\text{req}}$, $\text{out-deg}(v_i^{\text{req}}) > 0$ so $v_i^{\text{req}}$ naturally transitions out of $\mathcal{V}_{\text{frontier}}$; however, true terminal sink vertices ($\text{out-deg}(v) = 0$) are never evicted by TTL or cache pressure prior to epoch anchoring at $T_{\text{epoch}}$. Once a workflow session closes and its terminal sinks are durably anchored in $R_{T_{\text{epoch}}}$, those completed session sinks are checkpointed into the epoch log and compacted from the active in-memory frontier, keeping active frontier depth bounded ($\lceil \log_2 |\mathcal{V}_{\text{frontier}}| \rceil \in \{3, 4, 5\}$). Any historical vertex $v_k \notin \mathcal{V}_{\text{frontier}}(T_{\text{epoch}})$ is verified against anchored epoch root $R_{T_{\text{epoch}}}$ by composing its directed causal path $v_k = u_0 \to u_1 \to \dots \to u_r = v_f \in \mathcal{V}_{\text{frontier}}(T_{\text{epoch}})$ with an auxiliary causal-path witness tuple at each hop $u_j \to u_{j+1}$---comprising the non-private tuple fields of $u_{j+1}$ (Eq.~6), the sibling co-parent digests $\{H(w) \mid w \in \mathcal{P}(u_{j+1}) \setminus \{u_j\}\}$ at multi-parent merges (Eq.~5), and $v_f$'s epoch inclusion path $\mathcal{M}_{\text{path}}(T_{\text{epoch}})$. To fold $n = |\mathcal{V}_{\text{frontier}}|$ sorted digests $D_{1..n} = \langle H(v_1), \dots, H(v_n) \rangle$ (with $H(v_1) \le \dots \le H(v_n)$) into a canonical scalar root $R_T$, the gateway applies exact RFC 6962 Section~2.1 top-down recursive power-of-two splitting~\cite{laurie2014certificate}: for any single-element slice $D_{j..j}$, $H_{\text{tree}}(D_{j..j}) \triangleq \operatorname{SHA256}(\mathtt{0x00} \parallel D_j)$, and for any slice $D_{1..n}$ of length $n > 1$ with $k = 2^{\lfloor \log_2(n - 1) \rfloor}$ (the largest power of two strictly less than $n$), $H_{\text{tree}}(D_{1..n}) \triangleq \operatorname{SHA256}\big(\mathtt{0x01} \parallel H_{\text{tree}}(D_{1..k}) \parallel H_{\text{tree}}(D_{k+1..n})\big)$. Defining $H_{\text{tree}}(\mathcal{V}_{\text{frontier}}) \triangleq H_{\text{tree}}(D_{1..n})$, the top-level cardinality-binding envelope with domain prefix $\mathtt{0x05}$ is:
\begin{equation}
\begin{split}
R_T \triangleq \operatorname{SHA256}\Big(&\mathtt{0x05} \parallel \operatorname{encode}_{64}\big(|\mathcal{V}_{\text{frontier}}|\big) \\
&\parallel H_{\text{tree}}(\mathcal{V}_{\text{frontier}})\Big)
\end{split}
\end{equation}

\begin{theorem}[Causal Tamper Non-Interference]
Let $\mathcal{G}_{\text{prov}} = (\mathcal{V}, \mathcal{E})$ be an append-only Merkle-DAG with globally unique vertex IDs $\text{id}_v$, prefix-free length-prefixed serialization, and active frontier sink vertices $\mathcal{V}_{\text{frontier}} = \{v \in \mathcal{V} \mid \text{out-deg}_{\mathcal{G}_{\text{prov}}}(v) = 0\}$ committed into scalar root $R_T$ via Eq.~(7). Let reflexive-transitive precedence $\preceq$ be defined such that $u \preceq w \iff (u, w) \in \mathcal{E}^*$. For any vertex $v_k \in \mathcal{V}$, there exists at least one frontier sink $v_f \in \mathcal{V}_{\text{frontier}}$ such that $v_k \preceq v_f$. If an adversary (i) mutates any historical parameter/salt pair $(\theta_k, r_k) \to (\theta_k', r_k') \neq (\theta_k, r_k)$ on $v_c = v_k^{\text{req}}$, mutates any output payload $o_k \to o_k' \neq o_k$ on $v_c = v_k^{\text{resp}}$, or modifies the parent set $\mathcal{P}(v_c)$ of a surviving child vertex $v_c$ (via causal edge deletion, insertion, or parent substitution), or (ii) prunes any terminal branch or linear suffix from $\mathcal{G}_{\text{prov}}$, then every surviving descendant $v_d \in \mathcal{V}_{\text{desc}}(v_c) = \{v \in \mathcal{V}' \mid v_c \preceq v\}$ satisfies $H(v_d') \notin \{H(v) \mid v \in \mathcal{V}_{\text{desc}}(v_c)\}$ (and $H(v_f') \notin \{H(v) \mid v \in \mathcal{V}_{\text{frontier}}\}$ at the frontier), resulting in an altered frontier root $R_T' \neq R_T$ with probability at least $1 - (3L + 2|\mathcal{V}_{\text{frontier}}|) \cdot q / 2^{256}$ against a post-hoc adversary issuing $q$ random-oracle queries against an anchored $L$-vertex affected subgraph (and $1 - \binom{q + 3L + 2|\mathcal{V}_{\text{frontier}}|}{2} / 2^{256}$ against an adaptive collision adversary prior to root anchoring).
\end{theorem}
\begin{proof}
Follows from the multi-target second-preimage and collision resistance of SHA-256 under the random oracle model~\cite{merkle1987digital, bellare1993random}, where all eight Merkle-DAG invocation contexts ($\mathtt{0x00}$--$\mathtt{0x07}$, as well as auxiliary protocol contexts $\mathtt{0x08}$--$\mathtt{0x11}$) are unconditionally prefix-disjoint. Because $\mathcal{G}_{\text{prov}}$ is finite and acyclic, every vertex reaches at least one sink $v_f \in \mathcal{V}_{\text{frontier}}$. By prefix-free length-prefixed encoding ($\operatorname{lp}(\cdot), \operatorname{encode}_{64}(\cdot)$) over globally unique $\text{id}_v$ and fixed-width 32-byte digest slots in Eq.~(6) (and injective RFC 8785 JCS serialization inside $\mathtt{0x02}$ and $\mathtt{0x07}$), all honest vertices have distinct preimages under $\mathtt{0x04}$. In Case~(i), mutating $(\theta_k, r_k)$ alters $C_{\theta_k}' \neq C_{\theta_k}$ under $\mathtt{0x02}$, mutating $o_k$ alters $H_{\text{out}}(v_k^{\text{resp}\prime}) \neq H_{\text{out}}(v_k^{\text{resp}})$ under $\mathtt{0x07}$, and modifying $\mathcal{P}(v_c)$ (edge deletion/insertion altering $\operatorname{encode}_{64}(k_p)$, or parent substitution altering the sorted digest sequence) alters $H(\mathcal{P}'(v_c)) \neq H(\mathcal{P}(v_c))$ under $\mathtt{0x03}$. By topological induction over $v_d \in \mathcal{V}_{\text{desc}}(v_c)$, partitioning $\mathcal{P}(v_d)$ into mutated parents $\mathcal{P}_{\text{mut}}(v_d) = \mathcal{P}(v_d) \cap \mathcal{V}_{\text{desc}}(v_c)$ and unmutated parents $\mathcal{P}(v_d) \setminus \mathcal{V}_{\text{desc}}(v_c)$ (whose digests cancel identically in the multiset comparison), the inductive invariant $H(v_p') \notin \{H(v) \mid v \in \mathcal{V}_{\text{desc}}(v_c)\}$ for $v_p \in \mathcal{P}_{\text{mut}}(v_d)$ guarantees $H(\mathcal{P}'(v_d)) \neq H(\mathcal{P}(v_d))$ under $\mathtt{0x03}$ even across diamond merges, and thus $H(v_d') \notin \{H(v) \mid v \in \mathcal{V}_{\text{desc}}(v_c)\}$ (and $H(v_f') \notin \{H(v) \mid v \in \mathcal{V}_{\text{frontier}}\}$) under $\mathtt{0x04}$. In Case~(ii), pruning a terminal branch whose attachment ancestor retains $\text{out-deg}_{\mathcal{G}'_{\text{prov}}}(v_u) \ge 1$ (or removing a connected component) strictly reduces $|\mathcal{V}'_{\text{frontier}}| \neq |\mathcal{V}_{\text{frontier}}|$ under $\mathtt{0x05}$ in Eq.~(7). Conversely, truncating a linear terminal suffix where the immediate surviving predecessor had $\text{out-deg}_{\mathcal{G}_{\text{prov}}}(v_u) = 1$ (e.g., stripping $v_i^{\text{resp}}$ from $v_i^{\text{req}}$) or performing a balanced sink edit preserves $|\mathcal{V}'_{\text{frontier}}| = |\mathcal{V}_{\text{frontier}}|$ but promotes a non-frontier ancestor $v_u \in \mathcal{V} \setminus \mathcal{V}_{\text{frontier}}$ into a replacement sink $\mathcal{V}'_{\text{frontier}} = (\mathcal{V}_{\text{frontier}} \setminus \{v_f\}) \cup \{v_u\}$ with $H(v_u) \notin \{H(v) \mid v \in \mathcal{V}_{\text{frontier}}\}$ under $\mathtt{0x04}$, altering the sorted leaf digest vector $D_{1..n}$ inside $H_{\text{tree}}(\mathcal{V}_{\text{frontier}})$ under $\mathtt{0x00}/\mathtt{0x01}$. Because $\mathtt{0x02}$ ($v_i^{\text{req}}$) and $\mathtt{0x07}$ ($v_i^{\text{resp}}$) are mutually exclusive per vertex, each of the $L$ affected vertices invokes at most 3 fresh SHA-256 evaluations ($\mathtt{0x02}/\mathtt{0x07}, \mathtt{0x03}, \mathtt{0x04}$) and the frontier tree invokes $2|\mathcal{V}_{\text{frontier}}|$ evaluations ($n$ under $\mathtt{0x00}$, $n-1$ under $\mathtt{0x01}$, 1 under $\mathtt{0x05}$), yielding $3L + 2|\mathcal{V}_{\text{frontier}}|$ total target digests and the stated post-hoc and adaptive birthday bounds.
\end{proof}

\subsection{The Zero-Knowledge Action Attestation Voucher (ZKA-Voucher)}
As illustrated in Figure~\ref{fig:notary_arch}, when an agent invokes an external tool, the Agent-Notary Gateway intercepts the invocation frame, verifies $\Pi(t_i, \theta_i) = 1$, and synthesizes a canonical \textbf{ZKA-Voucher}:
\begin{equation}
\begin{split}
\mathcal{V}_{\text{wire}} = \langle &\text{vid}, R_{\text{merkle}}, H_{\text{leaf}}, H(\mathcal{P}_i^{\text{req}}), C_{\theta_i}, r_i^{\text{intra}}, a_i, t_i, \lambda_i, \\
&\tau_{\text{ns}}, \vec{\pi}_{\text{zk}}, \mathcal{M}_{\text{path}}, \sigma_{\text{notary}}, \text{kid}_{\text{notary}}, \text{pk}_{\text{notary}} \rangle
\end{split}
\end{equation}
where $\text{vid} \equiv \text{id}_i^{\text{req}}$ is the unique vertex/voucher UUID, $R_{\text{merkle}} \equiv R_T$ is the active frontier root at dispatch snapshot $T$, $H_{\text{leaf}} \equiv H(v_i^{\text{req}})$, $H(\mathcal{P}_i^{\text{req}})$ is the 32-byte parent-set digest required by the verifier to reconstruct candidate digest $H_{\text{leaf}}^*$ (throughout, superscript $(\cdot)^*$ denotes a candidate value recomputed independently by the verifier), $r_i^{\text{intra}} \equiv r_i$ is the 32-byte blinding opening carried exclusively on the intra-cluster hop to the tool server and stripped before persisting $\mathcal{V}_{\text{wire}}$ to external audit stores, $\tau_{\text{ns}}$ is the synchronized monotonic wall-clock timestamp, $\vec{\pi}_{\text{zk}} \triangleq \langle \pi_i, T_{\text{eval}}, C_{\text{circuit}}, x_i, \text{id}_{\Pi}, \texttt{session\_id}, \texttt{escrow\_mode} \rangle$ is the hot-path policy-attestation bundle (including a 1-byte $\operatorname{encode}_8(\texttt{escrow\_mode}) \in \{\mathtt{0x00},\mathtt{0x01}\}$ flag signaling whether the destination verifier must hold irreversible mutations in provisional escrow until Spanner epoch anchoring completes, and augmented asynchronously at epoch anchoring with Ristretto255 Pedersen commitments $\vec{C}_{\text{ped}}$ and Bulletproof transcript $\pi_i^{\text{pub}}$), $\mathcal{M}_{\text{path}}$ is the binary Merkle inclusion path, and $\sigma_{\text{notary}}$ is the cryptographic gateway authenticator.

\textbf{Dual-Mode Cryptographic Trust Model \& Per-Tool Key Isolation:} To reconcile sub-$5\,\mu\text{s}$ verification with third-party non-repudiation while preventing lateral voucher forgery across intra-cluster microservices:
\begin{enumerate}
    \item \textbf{Service-Bound Intra-Cluster Line-Rate Attestation:} Rather than sharing a single master secret $K_{\text{gateway}}$ across tool servers, the gateway enclave derives a service-specific verification key for each destination tool $t_i$ via RFC 5869 HKDF-SHA256 (where two-argument notation $\operatorname{HKDF-SHA256}(\text{ikm}, \allowbreak \text{info})$ denotes $\operatorname{HKDF-Expand}(\allowbreak\operatorname{HKDF-Extract}(\text{salt}_{\text{notary}}, \allowbreak \text{ikm}), \allowbreak \text{info}, L)$ with fixed domain-separated salt $\text{salt}_{\text{notary}}$):
    \begin{equation}
    \begin{split}
    K_{\text{tool}, t_i} = \operatorname{HKDF-SHA256}\big(&K_{\text{gateway}}, \\
    &\operatorname{lp}(t_i) \parallel \operatorname{lp}(\text{kid}_{\text{notary}})\big)
    \end{split}
    \end{equation}
    Each intra-cluster tool server $t_i$ is provisioned strictly with its scoped 32-byte key $K_{\text{tool}, t_i}$, ensuring that a compromised tool server $t_A$ cannot forge authenticators or witnesses for any other tool $t_B \neq t_A$. Using length-prefixed serialization $\operatorname{lp}(s) = \operatorname{encode}_{64}(|s|) \parallel s$ for variable-length strings and explicit 1-byte domain tags $\mathtt{0x0D}$ and $\mathtt{0x0E}$ for the bundle digests $\operatorname{SHA256}(\mathtt{0x0D} \parallel \operatorname{encode}(\vec{\pi}_{\text{zk}}))$---where $\operatorname{encode}(\vec{\pi}_{\text{zk}}) \triangleq \pi_i \parallel T_{\text{eval}} \parallel C_{\text{circuit}} \parallel x_i \parallel \operatorname{lp}(\text{id}_{\Pi}) \parallel \operatorname{lp}(\texttt{session\_id}) \parallel \operatorname{encode}_8(\texttt{escrow\_mode})$---and $\operatorname{SHA256}(\mathtt{0x0E} \parallel \operatorname{encode}(\mathcal{M}_{\text{path}}))$---where $\operatorname{encode}(\mathcal{M}_{\text{path}}) \triangleq \operatorname{encode}_{64}(|\mathcal{V}_{\text{frontier}}|) \parallel \operatorname{encode}_8(d_{\text{active}}) \parallel \operatorname{encode}_{32}(\text{dir\_mask}) \parallel S_1 \parallel \dots \parallel S_{d_{\text{active}}}$ over the $d_{\text{active}}$ active 32-byte sibling digests---$\sigma_{\text{notary}}$ authenticates all persistent voucher fields while intentionally excluding $r_i^{\text{intra}}$ so that stripping $r_i^{\text{intra}}$ prior to external archival preserves $\sigma_{\text{notary}}$ (while intra-cluster verifiers authenticate $r_i^{\text{intra}}$ via $C_{\theta_i}^* = C_{\theta_i}$ in Step~3, and external auditors treat $\pi_i$ and $C_{\theta_i}$ as opaque 32-byte inputs when recomputing Eq.~6):
    \begin{equation}
    \begin{split}
    \sigma_{\text{notary}} &= \operatorname{HMAC-SHA256}_{K_{\text{tool}, t_i}}\Big(\operatorname{lp}(\text{vid}) \parallel R_{\text{merkle}} \\
    &\parallel H_{\text{leaf}} \parallel H(\mathcal{P}_i^{\text{req}}) \parallel C_{\theta_i} \parallel \operatorname{lp}(a_i) \parallel \operatorname{lp}(t_i) \\
    &\parallel \operatorname{encode}_{64}(\lambda_i) \parallel \operatorname{encode}_{64}(\tau_{\text{ns}}) \\
    &\parallel \operatorname{SHA256}(\mathtt{0x0D} \parallel \operatorname{encode}(\vec{\pi}_{\text{zk}})) \\
    &\parallel \operatorname{SHA256}(\mathtt{0x0E} \parallel \operatorname{encode}(\mathcal{M}_{\text{path}})) \\
    &\parallel \operatorname{lp}(\text{kid}_{\text{notary}}) \parallel \text{pk}_{\text{notary}}\Big)
    \end{split}
    \end{equation}
    \item \textbf{Third-Party Public Non-Repudiation \& Cross-Domain Dispatch:} For external auditors (who never possess $K_{\text{gateway}}$ or $K_{\text{tool}, t_i}$), the gateway signs frontier epoch roots and policy attestation transcripts every $\Delta_{\text{epoch}} = 100\,\text{ms}$ using an asymmetric Ed25519 private key~\cite{bernstein2012ed25519} protected inside the Confidential VM enclave and bound to the enclave binary measurement via an AMD SEV-SNP hardware remote attestation quote $\mathcal{Q}_{\text{TEE}}$. Using 1-byte domain prefix $\mathtt{0x08}$, the batch epoch signature is $\Sigma_{\text{root}} = \operatorname{Sign}_{\text{Ed25519}}\big(\text{sk}_{\text{notary}}, \mathtt{0x08} \parallel \operatorname{encode}_{64}(\text{seq}_{\text{epoch}}) \parallel R_{\text{merkle}} \parallel \operatorname{encode}_{64}(\tau_{\text{epoch}}) \parallel H_{\text{epoch}}(\vec{\pi}_{\text{zk}})\big)$, where $H_{\text{epoch}}(\vec{\pi}_{\text{zk}})$ is the RFC 6962 Merkle root over the epoch's per-call commitment-equivalence leaves $L_{\text{eq}, i} = \operatorname{SHA256}\big(\mathtt{0x0C} \parallel C_{\text{circuit}} \parallel x_i \parallel C_{\theta_i} \parallel D_{\text{ped}, i} \parallel T_{\text{eval}} \parallel D_{\text{pub}, i}\big)$ with $\mathtt{0x0F}$-tagged proof digests $D_{\text{ped}, i} \triangleq \operatorname{SHA256}(\mathtt{0x0F} \parallel \vec{C}_{\text{ped}})$ and $D_{\text{pub}, i} \triangleq \operatorname{SHA256}(\mathtt{0x0F} \parallel \pi_i^{\text{pub}})$, verifiable publicly alongside $\mathcal{Q}_{\text{TEE}}$ using $\text{pk}_{\text{notary}}$. When a tool call crosses an organizational boundary synchronously to an external tool server lacking $K_{\text{tool}, t_i}$ (which still receives $(\theta_i, r_i^{\text{intra}})$ in plaintext to execute $t_i(\theta_i)$ and run Step~3), the gateway attaches an immediate on-demand $\mathtt{0x09}$-prefixed Ed25519 signature $\Sigma_{\text{cross}} = \operatorname{Sign}_{\text{Ed25519}}\big(\text{sk}_{\text{notary}}, \mathtt{0x09} \parallel R_{\text{merkle}} \parallel H_{\text{leaf}} \parallel \operatorname{encode}_{64}(\tau_{\text{ns}}) \parallel \operatorname{encode}_8(\texttt{escrow\_mode}) \parallel L_{\text{eq}, i}\big)$ via \texttt{x-agent-notary-crossdomain-sig} (verifiable in $62.4\,\mu\text{s}$ by the destination tool server; on the default $62.4\,\mu\text{s}$ cross-domain path where synchronous ZKP attachment is omitted, $L_{\text{eq}, i}$ in $\Sigma_{\text{cross}}$ sets $D_{\text{ped}, i} = D_{\text{pub}, i} = 0^{256}$ while the $100\,\text{ms}$ epoch root $H_{\text{epoch}}(\vec{\pi}_{\text{zk}})$ commits the populated $(\vec{C}_{\text{ped}}, \pi_i^{\text{pub}})$ digests, whereas when synchronous cross-domain ZKP attachment is enabled, $(\vec{C}_{\text{ped}}, \pi_i^{\text{pub}})$ are computed on demand and hashed directly into $L_{\text{eq}, i}$, and full third-party zero-knowledge verification of $\Sigma_{\text{root}} + \pi_i^{\text{pub}}$ when $(\theta_i, r_i^{\text{intra}})$ is withheld requires $840\,\mu\text{s}$).
\end{enumerate}

\textbf{Dual-Tier Blinded Policy-Invariant Attestation Engine:} To certify that private parameters satisfy policy constraints ($\Pi(t_i, \theta_i) = 1$) without exposing raw parameter values or allowing offline dictionary brute-forcing by external auditors, the engine formalizes the NP statement-witness relation over attribute scalars $v_{i,k} \in \mathbb{Z}_q$ (where $v_{i,k} = \theta_{i,k}$ for numeric attributes and $v_{i,k} = u_{i,k} \triangleq \operatorname{SHA256}(\theta_{i,k}) \bmod q$ for public string/URI attributes, or $u_{i,k} \triangleq \operatorname{HKDF-Expand}_{512}\big(\operatorname{HMAC-SHA256}(k_{\text{audit}}, \mathtt{0x10} \parallel \operatorname{lp}(\theta_{i,k})), \text{``allowlist-scalar''}\big) \bmod q$ when allowlist literals are confidential):
\begin{equation}
\begin{split}
\mathcal{R}_{\Pi} = \Big\{ &\big((t_i, C_{\theta_i}, \vec{C}_{\text{ped}}, x_i), (\theta_i, r_i)\big) \;\Big|\; C_{\theta_i} = \operatorname{Commit}(\theta_i; r_i) \\
&\land\; \Big(\bigwedge_{k=1}^{m} C_{\text{ped}, k} = g^{v_{i,k}} h^{r_{i,k}}\Big) \land \Pi(t_i, \theta_i) = 1 \Big\}
\end{split}
\end{equation}
where $x_i = \operatorname{SHA256}(\mathtt{0x0A} \parallel \operatorname{lp}(a_i) \parallel \operatorname{lp}(t_i) \parallel \operatorname{lp}(\texttt{session\_id}))$ is the domain-separated public context and $C_{\text{circuit}} = \operatorname{SHA256}(\mathtt{0x0B} \parallel \operatorname{lp}(\text{id}_{\Pi}) \parallel \operatorname{lp}(\text{type}_{\Pi}) \parallel \operatorname{lp}(\text{expr}_{\Pi}))$ is the policy circuit descriptor (committing to the expanded monic polynomial coefficients of $\prod_{w \in \mathcal{U}_{\text{allow}}}(u - w)$ when $\mathcal{U}_{\text{allow}}$ is confidential). Crucially, to prevent dictionary brute-forcing on low-entropy parameters $\theta_i$ (such as categorical enums or small numeric scalars), the blinded evaluation token $T_{\text{eval}}$ is keyed using an HKDF-derived blinding key extracted directly from the secret 256-bit commitment randomness $r_i \xleftarrow{\$} \{0,1\}^{256}$ rather than public identifiers:
\begin{equation}
\begin{split}
k_{\text{blind}, i} &= \operatorname{HKDF-SHA256}\big(r_i, \;\operatorname{lp}(\text{id}_{\Pi}) \parallel \operatorname{lp}(\text{vid})\big), \\
T_{\text{eval}} &= \operatorname{HMAC-SHA256}\big(k_{\text{blind}, i}, \;\operatorname{CanonicalJSON}(\theta_i)\big)
\end{split}
\end{equation}
Because $r_i$ has 256 bits of min-entropy and is withheld from external auditors, $(C_{\theta_i}, T_{\text{eval}}, \vec{C}_{\text{ped}})$ is computationally hiding under the PRF security of HKDF/HMAC-SHA256 (and binds $T_{\text{eval}}$ inside $L_{\text{eq}, i}$ for intra-cluster/epoch audit cross-checking). Attestation operates across two complementary tiers:
\begin{itemize}
    \item \emph{Tier 1 (Hot-Path Enclave Policy Witness, $0.77\,\mu\text{s}$):} On the synchronous tool-call critical path, no elliptic-curve scalar multiplications are executed. The trusted gateway enclave evaluates $\Pi(t_i, \theta_i) = 1$ in memory and issues a service-bound witness token $\pi_i = \operatorname{HMAC-SHA256}_{K_{\text{tool}, t_i}}(C_{\text{circuit}} \parallel x_i \parallel C_{\theta_i} \parallel T_{\text{eval}} \parallel \mathtt{0x01})$ (where trailing byte $\mathtt{0x01}$ encodes the compliance bit $\Pi(t_i, \theta_i) = 1$). Intra-cluster tool servers receive $(\theta_i, r_i^{\text{intra}})$ in plaintext to execute the operation, recomputing $C_{\theta_i}^*$, $H_{\text{leaf}}^*$ ($0.72\,\mu\text{s}$) and $k_{\text{blind}, i}^*$, $T_{\text{eval}}^*$, $\pi_i^*$ ($0.77\,\mu\text{s}$) without any elliptic-curve overhead.
    \item \emph{Tier 2 (Hybrid TEE-Bound Commitment Equivalence \& Zero-Knowledge Epoch Proofs):} To provide public auditability to untrusted third-party auditors when $(\theta_i, r_i^{\text{intra}})$ and $K_{\text{tool}, t_i}$ are withheld, the gateway asynchronously compiles an algebraic zero-knowledge proof $\pi_i^{\text{pub}}$ over the prime-order Ristretto255 group ($\mathbb{G}$ of order $q = 2^{252} + 27742317777372353535851937790883648493$) during $100\,\text{ms}$ epoch anchoring. For each of the $m$ policy-constrained JSON AST attributes ($v_{i,k} = \theta_{i,k} \in \mathbb{Z}_q$ for numeric fields and $v_{i,k} = u_{i,k}$ for string/URI fields), the gateway expands a 64-byte (512-bit) HKDF output before reducing modulo $q$, $r_{i,k} = \operatorname{HKDF-Expand}_{512}(r_i, \text{``pedersen''} \parallel \operatorname{encode}_{64}(k)) \bmod q$ (eliminating modulo bias to $< 2^{-256}$), and forms Pedersen commitments $C_{\text{ped}, k} = g^{v_{i,k}} h^{r_{i,k}} \in \mathbb{G}$~\cite{pedersen1991non}. Arbitrary numeric bounds $\theta_{i,k} \in [0, L_{\max}]$ are proven via dual 64-bit Bulletproof range constraints~\cite{bunz2018bulletproofs} on $C_{\text{ped}, k}$ ($\theta_{i,k} \in [0, 2^{64})$) and the homomorphically shifted slack commitment $g^{L_{\max}} C_{\text{ped}, k}^{-1} = g^{L_{\max} - \theta_{i,k}} h^{-r_{i,k}}$ ($L_{\max} - \theta_{i,k} \in [0, 2^{64})$), while finite allowlist set-membership polynomials $\prod_{w \in \mathcal{U}_{\text{allow}}} (u_{i,k} - w) = 0 \pmod q$ are compiled into Bulletproofs R1CS arithmetic-circuit multiplication gates ($|\mathcal{U}_{\text{allow}}| - 1$ gates per string attribute; when allowlist literals themselves are confidential, roots $w$ and $u_{i,k}$ are derived via $\mathtt{0x10}$-tagged $\operatorname{HMAC-SHA256}(k_{\text{audit}}, \cdot)$ so external auditors verify R1CS satisfaction against the committed polynomial coefficients in $C_{\text{circuit}}$ without learning raw allowlist strings unless provisioned with $k_{\text{audit}}$) with $(x_i, C_{\text{circuit}}, \text{vid})$ bound into the Fiat-Shamir challenge hash~\cite{fiat1986how}. We explicitly frame Tier~2 as a \emph{hybrid TEE-cryptographic trust model}: rather than executing a multi-second SHA-256/JSON-AST SNARK, the SEV-SNP-attested enclave ($\mathcal{Q}_{\text{TEE}}$) executes static commitment-binding logic to assert equivalence between $C_{\theta_i}$ and $\vec{C}_{\text{ped}}$ inside $L_{\text{eq}, i}$ under $\Sigma_{\text{root}}$, while $\pi_i^{\text{pub}}$ provides defense-in-depth algebraic zero-knowledge verification of policy predicates $\Pi$ using only $(\text{pk}_{\text{notary}}, \mathcal{Q}_{\text{TEE}}, g, h)$.
\end{itemize}

\subsection{Wire Protocol Encapsulation}
The ZKA-Voucher is serialized into a compact Base64 JSON token and injected into transport metadata:
\begin{itemize}
    \item \textbf{gRPC Metadata}: Attached as header \texttt{x-agent-notary-voucher}.
    \item \textbf{MCP JSON-RPC Frames}: Embedded into the top-level \texttt{headers} dictionary of \texttt{tools/call} requests, adhering to RFC 9421 header conventions~\cite{backman2024rfc9421}.
\end{itemize}
To ensure a predictable header footprint across active frontier depths $\lceil \log_2 |\mathcal{V}_{\text{frontier}}| \rceil \in \{3, 4, 5\}$, the wire serializer normalizes $\mathcal{M}_{\text{path}}$ to a canonical 4-slot sibling array (padding depth-3 paths with a zeroed 64-byte hex slot; unpadded paths across depths $\{3, 4, 5\}$ span $1{,}624$--$1{,}752$~B raw JSON). Across the $1{,}000$ benchmark traces under canonical 4-slot framing, raw JSON vouchers average $1{,}687.5$~B (ranging from $1{,}686$~B to $1{,}695$~B across variable-length tool names $t_i$). For a representative voucher ($1{,}688$~B raw JSON), the payload decomposes into $1{,}476$~B of field bundles (including nested sub-object delimiters)---metadata ($\text{vid}, a_i, t_i, \lambda_i, \tau_{\text{ns}}, \text{kid}_{\text{notary}}, \text{pk}_{\text{notary}}$) $= 280$~B, vertex/root hex digests ($R_{\text{merkle}}, H_{\text{leaf}}, C_{\theta_i}$) $= 192$~B, parent digest and intra-cluster salt ($H(\mathcal{P}_i^{\text{req}}), r_i^{\text{intra}}$: two $64$~B hex digests plus $2$~B delimiter) $= 130$~B, 4-slot Merkle path ($\mathcal{M}_{\text{path}}$: four $64$~B sibling hex digests plus $34$~B encoding the left/right bitmask, active depth, and frontier cardinality $|\mathcal{V}_{\text{frontier}}|$ for Eq.~7) $= 290$~B, hot-path policy attestation bundle ($\vec{\pi}_{\text{zk}}$) $= 520$~B, and authenticator ($\sigma_{\text{notary}}$) $= 64$~B---plus $212$~B of top-level JSON keys and delimiters. Base64 encoding yields $\lceil 1{,}688 \times 4 / 3 \rceil = 2{,}251$~B unpadded ($4\lceil 1{,}688 / 3 \rceil = 2{,}252$~B padded), with an empirical mean wire footprint of $2{,}250$~bytes (P50: $2{,}248$~B, P95: $2{,}256$~B, P99: $2{,}260$~B). Stripping $r_i^{\text{intra}}$ ($66$~B with delimiter) yields $1{,}622$~B raw JSON for external archival; when synchronous cross-domain ZKP attachment is enabled ($m=2$), \texttt{x-agent-notary-crossdomain-sig} adds $832$~B raw binary ($64$~B $\Sigma_{\text{cross}}$, $64$~B $\vec{C}_{\text{ped}}$, and $704$~B $\pi_i^{\text{pub}}$; $1{,}112$~B Base64).

\subsection{Line-Rate Intra-Cluster Verification Pipeline}
When a destination tool server receives an invocation, the embedded verifier executes five invariant checks in strictly bounded time ($< 50\,\mu\text{s}$ on the intra-cluster symmetric hot path):
\begin{enumerate}
    \item \textbf{Key Trust and Authenticator Invariant}: Evaluates $\sigma_{\text{notary}}$ against the gateway key registry using service-scoped $K_{\text{tool}, t_i}$ (or $\Sigma_{\text{cross}}$ via $\text{pk}_{\text{notary}}$ in $62.4\,\mu\text{s}$ for synchronous cross-domain calls).
    \item \textbf{Timestamp Freshness and Anti-Replay}: Asserts $|\tau_{\text{now}} - \tau_{\text{ns}}| \le \Delta_{\text{TTL}}$ ($5\text{ minutes}$) and checks $\text{vid}$ against an in-memory lock-free ring-buffer replay cache ($0.12\,\mu\text{s}$ lookup included within the $0.68\,\mu\text{s}$ Steps~1--2 check); to prevent in-transit tampering of unauthenticated plaintext $(\theta_i, r_i^{\text{intra}})$ from poisoning $\text{vid}$ before Step~3, atomic $\text{vid}$ insertion into the replay cache is deferred until Steps~3--5 succeed on both intra-cluster and cross-domain paths.
    \item \textbf{Parameter \& Leaf Binding Invariant}: Asserts $t_i$ matches the local tool identity and reconstructs $C_{\theta_i}^*$ and $H_{\text{leaf}}^*$ via Eqs.~(2) and (6) from incoming $\theta_i, r_i^{\text{intra}}$ and voucher fields $(\text{vid}, a_i, \lambda_i, H(\mathcal{P}_i^{\text{req}}), t_i, H_{\text{pending}}, \pi_i)$ (where cross-domain verifiers treat $\pi_i$ as an opaque 32-byte field), asserting $C_{\theta_i}^* = C_{\theta_i}$ and $H_{\text{leaf}}^* = H_{\text{leaf}}$ in $0.72\,\mu\text{s}$.
    \item \textbf{Merkle Frontier Inclusion}: Evaluates $\mathcal{M}_{\text{path}}$ with $\mathtt{0x00}/\mathtt{0x01}/\mathtt{0x05}$ domain prefixes against $R_{\text{merkle}}$ in $O(\log |\mathcal{V}_{\text{frontier}}|)$ time ($0.58\,\mu\text{s}$), binding $H_{\text{leaf}}$ to the frontier root logged for asynchronous epoch cross-checking.
    \item \textbf{Policy-Invariant Witness \& Escrow Verification}: Asserts $C_{\text{circuit}}$ matches the local administrator-provisioned descriptor for $t_i$ and recomputes $x_i^*, k_{\text{blind}, i}^*, T_{\text{eval}}^*$ from $(r_i^{\text{intra}}, \theta_i, a_i, t_i, \text{id}_{\Pi}, \text{vid}, \texttt{session\_id})$: intra-cluster verifiers assert $\pi_i^* = \pi_i$ in $0.77\,\mu\text{s}$, while cross-domain verifiers assert $L_{\text{eq}, i}^* = L_{\text{eq}, i}$ under $\Sigma_{\text{cross}}$ (and verify $\pi_i^{\text{pub}}$ when attached). If $\texttt{escrow\_mode} = 1$ (authenticated in $\sigma_{\text{notary}} / \Sigma_{\text{cross}}$ or mandated by the local static tool policy table for irreversible mutations), the verifier holds execution until receiving the signed epoch bundle $(\text{seq}_{\text{epoch}}, R_{\text{merkle}}, \tau_{\text{epoch}}, H_{\text{epoch}}(\vec{\pi}_{\text{zk}}), \Sigma_{\text{root}})$ and verifying an RFC 6962 Merkle inclusion proof of $L_{\text{eq}, i}$ in $H_{\text{epoch}}(\vec{\pi}_{\text{zk}})$ under $\Sigma_{\text{root}}$ (failing closed if anchoring exceeds $250\,\text{ms}$).
\end{enumerate}

\subsection{Part 2: Multi-Agent Indirect Prompt-Injection Evaluation (\texorpdfstring{$N = 300$}{N = 300})}
We further evaluated Agent-Notary against $N = 300$ live multi-agent indirect prompt-injection scenarios adapted equally ($100$ traces each) from standardized agent security suites (AgentDojo~\cite{debenedetti2024agentdojo}, InjecAgent~\cite{zhan2024injecagent}, and ASB~\cite{zhang2025asb}) across a 3-agent swarm (Customer Intake Agent $a_1 \to$ Workflow Planner $a_2 \to$ Treasury/Storage Executor $a_3$ on Vertex AI Gemini 2.5 Flash), where each tool $t_i$ is governed by $m = 2$ policy invariants $\Pi(t_i, \theta_i)$ (a numeric upper bound $\theta_{\text{amt}} \in [0, \$10{,}000]$ and an 8-element corporate URI/recipient allowlist $|\mathcal{U}_{\text{allow}}| = 8$; tasks from the source benchmarks were mapped into structured parameter schemas so pre-execution $\Pi = 0$ checks evaluate numeric caps and destination allowlists, while unconstrained free-text semantic hijackings fall under $\Pi = 1$ post-hoc attribution):
\begin{enumerate}
    \item \textbf{Pre-Execution Blocking of Out-of-Policy Prompt Injections ($\Pi(t_i, \theta_i) = 0, n = 200$):} Untrusted external tickets embedded indirect prompt injections coercing $a_3$ into invoking wire-transfer or storage-export tools violating $\Pi(t_i, \theta_i)$ ($\theta_{\text{amt}} > \$10{,}000$ or external URIs $\notin \mathcal{U}_{\text{allow}}$). \section{Discussion and Enterprise Cloud Integration}
Agent-Notary natively integrates into Google Cloud infrastructure, specifically Vertex AI Agent Builder, Gemini Enterprise, and Cloud Logging:
\begin{enumerate}
    \item \textbf{Vertex AI Extension Interceptor}: Acts as a transparent proxy mediating between Vertex AI Agent reasoning engines and external Enterprise APIs (e.g., BigQuery, SAP, Workday).
    \item \textbf{Model Context Protocol (MCP) Gateway Sidecar}: Serves as an auditable MCP sidecar, authenticating JSON-RPC tool frames across multi-tenant clusters.
    \item \textbf{State Persistence and Distributed Frontier Synchronization}: In session-sticky deployments where a swarm session ($\texttt{session\_id}$) routes through a designated gateway replica, frontier roots ($R_{\text{merkle}}$) are updated in local enclave memory at the $28.45\,\mu\text{s}$ latency reported in Table~\ref{tab:latency_profile}. When a swarm spans horizontally auto-scaled gateway replicas (benchmarked across 3 \texttt{c3-standard-8} nodes), sidecars synchronize session-sharded frontier head hashes ($v_i^{\text{req}}, v_i^{\text{resp}}$) and monotonic Lamport counters via pipelined atomic Lua scripts (\texttt{EVALSHA} followed by synchronous replica acknowledgment \texttt{WAIT 1} with a $5\,\text{ms}$ timeout) on Google Cloud Memorystore for Redis, atomically validating monotonic lease fencing tokens issued by Cloud Spanner / etcd inside the \texttt{EVALSHA} script prior to state mutation (adding $+185\,\mu\text{s}$ P50 and $+390\,\mu\text{s}$ P99 cross-replica coordination overhead) and reconciling per-replica NVMe vertex journals prior to $100\,\text{ms}$ Cloud Spanner TrueTime epoch anchoring~\cite{corbett2013spanner} (where $\text{seq}_{\text{epoch}}$ is incremented in enclave memory every $100\,\text{ms}$ under Spanner TrueTime monotonicity and sealed to the SEV-SNP/TPM hardware counter upon enclave initialization and key rotation). If a transient partition or \texttt{WAIT 1} timeout ($> 5\,\text{ms}$) triggers local NVMe fallback, the gateway sets $\texttt{escrow\_mode} = 1$ in $\vec{\pi}_{\text{zk}}$, instructing the destination verifier's outbound proxy to hold irreversible external REST/gRPC mutations until the corresponding Spanner epoch root $\Sigma_{\text{root}}$ is published (upon lease takeover, the successor replica merges any unanchored NVMe/Redis causal sinks into the active frontier prior to signing $\Sigma_{\text{root}}$).
\end{enumerate}

\section{Conclusion}
The rapid proliferation of autonomous generative agent swarms demands a transition from unauthenticated textual logs to cryptographically verifiable action provenance. We introduced \textbf{Agent-Notary}, a line-rate framework combining append-only two-phase Causal Merkle-DAGs, Dual-Tier Blinded Policy-Invariant Attestation, and wire-level ZKA-Vouchers. Across $1{,}000$ wire-tampering traces and $300$ multi-agent prompt-injection traces, Agent-Notary delivers $100.00\%$ detection of parameter tampering, signature forgery, and out-of-policy injections alongside $100.00\%$ post-hoc causal attribution at a mean intra-cluster verification latency of $4.17\,\mu\text{s}$, establishing an auditable and non-repudiable foundation for enterprise multi-agent deployment.
